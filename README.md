# Кварта — лендинг кофейной мастерской

Я делал этот проект как разработчик: собрал лендинг, связал форму с серверной частью и продумал, как оператору работать с заявками. Для меня это была не только задача сверстать страницу — нужно было пройти путь от отправки формы до обработки заказа.

## Как запустить локально

Нужен Python 3.10 или новее.

1. Установить зависимости: `pip install -r requirements.txt`.
2. Скопировать `.env.example` в `.env` и заполнить настройки. Для локальной страницы без Telegram можно оставить токен бота пустым.
3. Запустить `python main.py` и открыть [http://localhost:8000](http://localhost:8000).

Локально заявки хранятся в `leads.sqlite3`. Файл `.env` и база в Git не попадают.

## Что я сделал

Я определил, что должно происходить с заявкой и как оператор будет с ней работать. Форма проверяет белорусский номер, сервер ограничивает частые отправки и не создаёт повторную заявку с тем же номером в течение десяти минут. На Vercel заявки сохраняются в Neon Postgres, а локально — в SQLite.

Для Telegram я описал нужный процесс и проверял его по ходу работы: заявка приходит отдельной карточкой; «В работу» добавляет её в заказы; отклонённые и завершённые записи остаются в истории. Для комментариев к заявке можно добавить заметку с подписью автора, а для обратного звонка — поставить напоминание на выбранное время. `/leads` и кнопки «Активные заказы» и «Все заказы» показывают списки заявок и заказов.

Я также сам проверял страницу в браузере и давал конкретные замечания по результату: увеличивал мелкий текст, исправлял мобильную компоновку, убирал обрезанные элементы и уточнял поведение формы. ИИ помогал писать и менять части HTML, CSS, JavaScript и Python. Я проверял эти изменения и возвращал их на доработку, когда визуальный результат или поведение не совпадали с задачей. Этапы работы и примеры замечаний собраны в [журнале проекта](docs/ai-work-log.md) и [записях диалога](docs/ai-session-log.md).

## Как пользоваться заявками

На опубликованном сайте посетитель отправляет форму. Чтобы Telegram начал принимать карточки, получатель `@wxnasleep` должен один раз открыть бота и отправить `/start`. После этого новые заявки приходят в чат: оттуда можно позвонить, принять заявку в работу или отклонить её, добавить заметку и назначить напоминание. `/leads` показывает текущие заявки и заказы; кнопка «Все заказы» показывает записи вместе с их статусами.

Напоминания запускаются внешним планировщиком cron-job.org раз в минуту. Расписание вызывает защищённый `/api/cron`; секрет хранится в настройках сервиса, не в репозитории.

## Публикация и проверка

Сайт опубликован на [Vercel](https://tz-lending.vercel.app), заявки на production хранятся в Neon Postgres. Telegram webhook принимает команды и кнопки бота. Переменные окружения и токен не хранятся в Git; локальные значения берутся из `.env`, production-настройки — из Vercel.

Мобильный Lighthouse для локальной версии: производительность — 90, доступность — 96, лучшие практики — 100, SEO — 100. [HTML-отчёт](reports/lighthouse-mobile.report.html) и [JSON-результат](reports/lighthouse-mobile.report.json) лежат в `reports/`.

Перед реальным использованием я бы заменил примерный телефон на рабочий, добавил страницу о персональных данных и проверил полный сценарий заявки на телефоне и в Telegram.
